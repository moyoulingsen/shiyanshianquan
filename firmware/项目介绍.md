# LabGuard 单板项目介绍

## 一、项目概述

`LabGuard SingleP4` 是一套面向高校和科研实验室场景的智能安全系统。系统采用**一块 `ESP32-P4-Function-EV-Board`** 完成完整闭环：视觉识别、环境感知、风险融合、声光联动、排风控制与云端告警都在同一控制器上实现。

- 板载视觉模块负责 PPE 合规检测、烟雾/明火隐患识别。
- 板载传感模块负责温湿度、VOC、烟雾等环境数据采集。
- 板端融合模块根据视觉与传感器结果输出风险等级。
- 板端执行模块负责风扇、水泵、声光告警等联动。
- 通过 Wi‑Fi 与 MQTT 把状态同步到网页端和手机端。

## 二、应用场景与痛点

实验室管理常见问题主要集中在三类：

1. 人员进入实验室前未按要求穿实验服、护目镜等 PPE。
2. 实验进行中出现烟雾、火焰、温度异常、空气质量恶化等风险，传统人工巡查响应慢。
3. 监测、告警、联动处置通常彼此割裂，缺少统一闭环。

本项目针对这些问题，将识别、监测和处置整合到一块板子上，做到：

- PPE 不合格时即时提示并限制进入。
- 识别到火焰/烟雾或传感器异常时自动触发联动。
- 关键状态和事件通过 MQTT 上报，便于网页端或上位机接入。
- 减少多板协同复杂度，便于部署、演示和后续落地。

## 三、系统架构

### 1. 单板核心节点

主要硬件包含：

- `ESP32-P4-Function-EV-Board`
- `OV2740 MIPI CSI` 摄像头
- `SHT30` 温湿度模块
- `ENS160` VOC/空气质量模块
- `MQ-2` 烟雾/可燃气体模块
- `5V` 风扇
- `5V` 微型水泵
- `4 路 MOSFET` 驱动板
- 小喇叭 / 声光报警器
- `WS2812B` 状态灯效

主要功能：

- 采集实验室图像与环境数据。
- 判断是否存在 PPE 不合规、烟雾、火焰或气体异常。
- 融合多源信息生成风险等级。
- 根据风险等级执行风扇、水泵、报警联动。
- 通过屏幕、语音和指示灯进行交互提示。

### 2. 通信与协同

单板接入同一 `2.4GHz Wi‑Fi` 网络，通过 MQTT 交换状态：

- 板端发布 `vision`、`sensor`、`risk`、`action`。
- 管理端可通过 `cmd/reset`、`cmd/test` 等 topic 下发控制命令。
- 网页端和手机端读取统一状态，不再区分门外/门内节点。

## 四、软件设计

```text

│  ├─ labguard_common/

│  ├─ event_log/
│  └─ espdl_probe/

├─ vision/
└─ tools/
```

## 2. 核心软件模块

- `main/`：单板主循环入口。
- `labguard_common/`：状态结构体、JSON 编解码、风险等级定义。
- `labguard_net/`：Wi‑Fi 与 MQTT 封装。
- `event_log/`：记录最近事件，统一发布格式。
- `espdl_probe/`：ESP-DL 模型加载/测试探针。

## 3. 核心流程

### 1. 单板感知流程

1. 摄像头采集实验室画面。
2. 视觉模块输出 PPE、烟雾、火焰结果。
3. 传感模块读取温湿度、VOC、烟雾告警状态。
4. 风险引擎综合判断：
   - `normal`
   - `warning`
   - `alarm`
   - `emergency`
5. 执行模块按等级执行联动：
   - `warning`：仅提示
   - `alarm`：报警 + 风扇
   - `emergency`：报警 + 风扇 + 水泵
6. 发布统一状态给网页端、手机端和上位机。

### 2. 命令控制

系统支持通过 MQTT 切换演示或测试场景：

- `reset`
- `selftest`
- `force_normal`
- `force_warning`
- `force_alarm`
- `force_emergency`

## 五、创新点

### 1. 单板闭环

系统把视觉识别、环境监测、风险判断和联动处置集中在一块板子上，减少节点间同步与部署复杂度。

### 2. 多源信息融合

风险判断同时考虑视觉识别、温度、VOC、MQ-2 告警等多源信息，比单一阈值触发更稳健。

### 3. 边缘端数据平滑

系统在 ESP32-P4 侧对传感器数据进行卡尔曼滤波，降低瞬时噪声造成的误触发，并在 UI 与 MQTT 数据中保留原始值和滤波值，方便演示和调参。

### 4. 强交互性

系统包含触摸屏状态面板、语音播报、灯光提示、最近事件记录和网络消息，具备完整的 AIoT 人机交互链路。

### 5. 演示与实装兼容

当前代码已支持“模拟场景演示模式”，同时保留了摄像头、传感器、执行器、LVGL、音频的清晰接口，便于比赛前快速演示，也便于后续接真实硬件。

## 七、后续落地建议

当前仓库已经具备完整业务逻辑，但真实硬件驱动仍建议按下面顺序替换：

1. 先把 Wi‑Fi/MQTT 参数改为 `menuconfig` 配置。
2. 对接真实 `OV2740` 采集驱动。
3. 用真实 `SHT30 / ENS160 / MQ-2` 替换传感器模拟数据。
4. 用真实 `GPIO/PWM/MOSFET` 实现舵机、风扇、水泵、WS2812B 控制。
5. 把视觉模块替换成 ESP-DL 模型推理。
6. 把 `event_log` 扩展为 TF 卡存储。

## 八、总结

`LabGuard SingleP4` 通过一块 `ESP32-P4` 把实验室门禁准入、危险识别和自动联动处置整合为一个完整 AIoT 系统。项目既适合课程设计、比赛演示，也适合作为后续真实实验室安全终端的原型基础。
